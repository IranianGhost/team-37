# Software Engineering – Phase 1

Welcome to Phase 1 of the Software Engineering course project.

This repository contains the assignment description and scenario cards required for this phase.

## 1. Team Formation

- Each team must consist of exactly two students.
- Each team must have a unique team number.
- Both team members are responsible for participating in the project activities.

## 2. Create Your Team Repository

Each team must create its own repository by forking this repository.

1. Open this repository.
2. Click the **Fork** button.
3. Select the course GitHub Organization as the destination owner.
4. Set your repository name to `team-XX`, replacing `XX` with your team number.

For example:
- `team-01`
- `team-02`
- `team-15`

5. Click **Create fork**.

Make sure your repository is created under the course Organization, not your personal GitHub account.

## 3. Select Your Scenario

Each team is assigned a scenario card corresponding to its team number.

Find your team's scenario card in the `scenarios/` directory.

All assignment activities must be based on your assigned scenario.

## 4. Working on Your Repository

Your team's repository is the workspace for all project activities and deliverables.

- Both team members should actively participate in the work.
- Create and organize files according to the assignment requirements.
- Commit your work regularly throughout the assignment.
- Use meaningful commit messages.
- Preserve your commit history as evidence of your work process.
- Do not rewrite or delete commit history.

## 5. Peer Review

Each team will be paired with another team for peer review.

The assigned pairings will be announced separately.

You are expected to review your paired team's work according to the assignment instructions and provide constructive, evidence-based feedback.

## 6. Submission

Your team's GitHub repository is the primary record of your work.

Before the deadline, make sure that:

- All required deliverables are committed and pushed.
- All files follow the paths and naming conventions specified in the assignment.
- Both team members have contributed to the work.
- The repository is accessible to the course staff.

**Deadline:** To be announced.

## 7. Important Notes

- Do not modify the original course repository.
- Do not create a new repository from scratch; use the Fork workflow.
- Do not fork another team's repository.
- Do not submit Pull Requests to the original course repository.
- Follow the assignment document for detailed requirements and evaluation criteria.

Good luck!
